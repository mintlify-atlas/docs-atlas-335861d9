---
title: 'Authenticate Leantime API requests'
description: 'Leantime supports two authentication methods for API access: Leantime API keys and Laravel Sanctum Bearer tokens via the AdvancedAuth plugin.'
---

Every request to the Leantime JSON-RPC API must be authenticated. Unauthenticated requests are rejected before they reach the service layer. Leantime supports two authentication methods: API keys built into Leantime, and personal access tokens issued by Laravel Sanctum (available with the AdvancedAuth plugin).

## Method 1: Leantime API keys

API keys are the primary authentication method. Each key acts as a service account with its own user record and role inside Leantime.

### Key format

```
x-api-key: lt_{username}_{apikey}
```

The key is a composite of:
- `lt_` — literal prefix
- `{username}` — the name you give the API key when you create it
- `{apikey}` — the secret generated by Leantime

### Create an API key

<Steps>
  <Step title="Open settings">
    In the Leantime sidebar, navigate to **Settings**.
  </Step>
  <Step title="Go to API Keys">
    Select **API Keys** from the settings menu.
  </Step>
  <Step title="Create a new key">
    Click **Add API Key**, enter a name (this becomes the `{username}` segment), choose a role, and save.
  </Step>
  <Step title="Copy the secret">
    Leantime displays the full key string once. Copy it immediately — it is not shown again.
  </Step>
</Steps>

<Warning>
  Store your API key in a secrets manager or environment variable. Anyone who has the key can make API calls with the permissions of the associated account.
</Warning>

### Send the key

Pass the API key in the `x-api-key` header on every request:

<CodeGroup>

```bash curl
curl -X POST https://your-leantime.example.com/api/jsonrpc \
  -H "Content-Type: application/json" \
  -H "x-api-key: lt_myuser_abc123secret" \
  -d '{
    "jsonrpc": "2.0",
    "method": "leantime.rpc.tickets.getTicket",
    "params": { "id": 1 },
    "id": 1
  }'
```

```php PHP
$response = (new \GuzzleHttp\Client())->post('https://your-leantime.example.com/api/jsonrpc', [
    'headers' => [
        'Content-Type' => 'application/json',
        'x-api-key'    => 'lt_myuser_abc123secret',
    ],
    'json' => [
        'jsonrpc' => '2.0',
        'method'  => 'leantime.rpc.tickets.getTicket',
        'params'  => ['id' => 1],
        'id'      => 1,
    ],
]);
$data = json_decode($response->getBody(), true);
```

```javascript JavaScript
const response = await fetch('https://your-leantime.example.com/api/jsonrpc', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'x-api-key': 'lt_myuser_abc123secret',
  },
  body: JSON.stringify({
    jsonrpc: '2.0',
    method: 'leantime.rpc.tickets.getTicket',
    params: { id: 1 },
    id: 1,
  }),
});
const data = await response.json();
```

</CodeGroup>

## Method 2: Bearer tokens (AdvancedAuth plugin)

If the **AdvancedAuth** plugin is installed, users can create personal access tokens and use them to authenticate API requests as themselves. The token authenticates with Laravel Sanctum.

<Note>
  Bearer token authentication requires the AdvancedAuth plugin. It is not available in the base open-source release.
</Note>

### Create a personal access token

Personal access tokens are created from a user's profile or account settings once the AdvancedAuth plugin is active. Each token inherits the permissions of the user who created it.

### Send the token

Pass the token in the `Authorization` header:

<CodeGroup>

```bash curl
curl -X POST https://your-leantime.example.com/api/jsonrpc \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-personal-access-token" \
  -d '{
    "jsonrpc": "2.0",
    "method": "leantime.rpc.tickets.getTicket",
    "params": { "id": 1 },
    "id": 1
  }'
```

```php PHP
$response = (new \GuzzleHttp\Client())->post('https://your-leantime.example.com/api/jsonrpc', [
    'headers' => [
        'Content-Type' => 'application/json',
        'Authorization' => 'Bearer your-personal-access-token',
    ],
    'json' => [
        'jsonrpc' => '2.0',
        'method'  => 'leantime.rpc.tickets.getTicket',
        'params'  => ['id' => 1],
        'id'      => 1,
    ],
]);
```

```javascript JavaScript
const response = await fetch('https://your-leantime.example.com/api/jsonrpc', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': 'Bearer your-personal-access-token',
  },
  body: JSON.stringify({
    jsonrpc: '2.0',
    method: 'leantime.rpc.tickets.getTicket',
    params: { id: 1 },
    id: 1,
  }),
});
```

</CodeGroup>

## Choosing an authentication method

| | API key (`x-api-key`) | Bearer token |
|---|---|---|
| Available without plugins | Yes | No (requires AdvancedAuth) |
| Acts as a service account | Yes | No — acts as the token owner |
| Suitable for server-to-server | Yes | Yes |
| Per-user access control | Via role assigned to key | Inherits user's permissions |

Use API keys for server-to-server integrations, automation, and scripts. Use Bearer tokens when you need requests to carry a specific user's identity and permissions.

## Error responses

### Missing or invalid credentials

```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32600,
    "message": "Invalid Request",
    "data": "Unauthorized"
  },
  "id": null
}
```

An HTTP `401` status is returned when no valid credentials are provided.

### Insufficient permissions

When a valid key or token is present but the associated account lacks the required role or project access, Leantime returns an HTTP `403` response. The JSON body format is the same as above with a `"Forbidden"` data value.
